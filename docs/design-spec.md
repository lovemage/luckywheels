# 幸運輪盤設計規範

## 目標

本專案是 LINE 會員抽獎活動頁，目標視覺需接近參考圖的紫金色高級抽獎風格。前台優先服務手機使用者，畫面需讓業主一眼看出「幸運輪盤、會員可抽獎、點擊抽獎、查看獎品」四件事。

目前前台展示版以 `430x932` 手機比例為主要設計基準，桌面環境則同時展示手機前台與 Admin 後台。

### 2026-06-03 業主會議結論補充

- 中獎內容為**彩金（現金獎金）**，輪盤上每一格獎項對應一個 `cashAmount`。實體禮品延後處理，但視覺結構仍保留圖示位，後期可換成實體禮品照。
- **頭獎為固定金額獎項**，不採累積機制。頭獎到六獎各自有固定 `cashAmount`，由 Admin 後台設定。
- 排行榜頁面分為**消耗排行榜**與**幸運排行榜**兩個分頁。
- 帳號分**正式會員（verified）**與**測試帳號（test）**。測試帳號的 UI 行為可由 Admin 透過後台覆寫，但前端視覺上需與正式會員一致，避免被外部察覺。

## 視覺方向

- 主題：高級感、熱鬧、活動感、紫金色抽獎遊戲。
- 主色：深紫、亮紫、金色、洋紅緞帶。
- 質感：bitmap 3D 元件優先，避免只用 CSS/SVG 畫出扁平感。
- 氣氛：舞台光、金幣、紙花、發光燈泡、金色金屬邊框。
- 文字：所有可變文字盡量用 HTML/CSS 呈現，避免圖片文字在後台改獎品時失效。

## 手機頁面區塊

### 1. 背景

背景使用 `lucky-bg.png` 滿版覆蓋手機容器。

規範：

- 背景應保留中間輪盤區的可讀性。
- 金幣與紙花可出現在邊緣，但不可遮擋主 CTA、底部選單、會員面板。
- 底部舞台地板需保留，增加接近原圖的場景感。

### 2. 左上 Logo

使用：

```text
public/assets/logo.png
```

規範：

- Logo 位置在左上。
- 不要用程式重畫 logo。
- Logo 不可壓到右上會員面板。
- Logo 圖片本身包含皇冠、主標、緞帶副標。

### 3. 會員面板

位置：右上。

內容（依 2026-06-03 業主反饋與後續積分制調整）：

- 會員頭像
- 會員專區
- LINE 會員名稱
- **積分**（會員當前積分餘額，由 Admin 派發、抽獎扣抵）
- **可抽次數**（由「積分階層表」推導，前端不可手動填寫）
- **累計抽獎次數**

規範：

- 面板不得擋住輪盤主要獎品區。
- 手機版面板寬度目前約 `172px`。
- 背景為半透明紫色玻璃感，但不可過度模糊。
- 積分與次數需高對比可讀。
- **不放 VIP 等級徽章**。原本硬編碼的「VIP 3」已移除，正式版會員等級若需呈現需依後台資料動態給值，不可寫死。
- 「可抽次數」的計算遵循「集點抽獎門檻」表：找出最大的 `threshold.points ≤ 目前積分`，取其 `draws` 值。預設門檻表為：

  | 集滿積分 | 可抽次數 |
  |---:|---:|
  | 6 | 1 |
  | 15 | 3 |
  | 25 | 5 |
  | 35 | 7 |
  | 48 | 10 |

### 4. 輪盤

輪盤由兩層組成：

```text
外框：public/assets/wheel-frame.png
內盤：CSS conic-gradient 動態扇形
```

規範：

- 外框、燈泡、指針固定不動。
- 只有內盤與獎品內容旋轉。
- 中央旋鈕為 `50x50`，純裝飾元件，不放任何文字、不可被點擊（抽獎一律走下方主 CTA）。
- 獎品內容需保留足夠面積，不可貼到外框。
- 輪盤每個位置的獎品、排序與機率需由 Admin 控制，前端不可寫死。
- **輪盤總格數固定為 6 格**（2026-06-03 業主會議結論）。前端與 Admin 後台都應以 6 為預設值；如未來改變總格數，需同步更新分隔線、扇形角度、獎品定位演算法。
- 輪盤外圍的可視金環需以手機螢幕為基準，**外框邊緣與螢幕兩側保持約 10px 間距**。實作上以容器寬度 `min(calc(100vw - 20px), 410px)` 作為盤面基準，再讓外框圖層額外延伸（約 1.08 倍）以推齊可視金環。

#### 獎品對齊規範

- 第一格中心需對齊 12 點鐘（頂端指針位置）。
- `wheel-face` 的 `conic-gradient` 起始角為 `from -30deg`，使第 0 格（頭獎）的中心落在 12 點，順時針依序為二、三、四、五、六獎。
- 獎品標籤角度公式為 `angle = (360 / total) * index`（不再加半段偏移），與 conic-gradient 對齊；對應的抽獎落點公式 `targetCenter = index * segmentSize`。

#### 盤面配色規範（每格獨立色）

- 不再使用原本「紫色 / 黃色（cream）兩色交替」的盤面背景。
- 每一格擁有獨立的 `segmentColor` 與 `textColor`，由獎品資料攜帶，前端不寫死。
- 預設 6 格採用 6 種對比明顯的色相，盤面整體偏向經典遊樂場彩輪：

  | 位置 | segmentColor | textColor |
  |---|---|---|
  | 頭獎 | `#d92b3a` 朱紅 | `#fff5d6` |
  | 二獎 | `#ec8a26` 琥珀 | `#fff5d6` |
  | 三獎 | `#c98612` 金黃 | `#fff5d6` |
  | 四獎 | `#38a86e` 翡翠 | `#fff5d6` |
  | 五獎 | `#2e7cd9` 寶藍 | `#fff5d6` |
  | 六獎 | `#9b3eb8` 紫晶 | `#fff5d6` |

- 文字 `textColor` 全格統一為米白 `#fff5d6`，避免不同格使用不同文字色造成「三獎暗、其它亮」的觀感差異（2026-06-03 業主反饋）。
- 為了讓米白文字在所有底色上都有足夠對比，三獎原本的明黃 `#f4cb3a` 改為較深的金黃 `#c98612`，其餘格底色維持較深的飽和色。
- 文字統一加深色描邊或陰影，進一步補強可讀性。
- **不畫獨立的分隔線**。每一格之間以「相鄰兩格 segmentColor 的色相差」當作視覺邊界，不再疊一條金色細線（2026-06-03 業主反饋：金色線條與多色底重疊會產生多餘的視覺雜訊）。實作上以 `conic-gradient` 的硬邊色階直接形成邊界即可。
- 中央旋鈕、外框、燈泡仍維持金色系。

### 5. 輪盤獎品內容

每格顯示：

- 獎項等級，例如 `頭獎`
- 獎品名稱或彩金描述，例如 `iPhone 15`、`超商禮券`
- 補充說明，例如 `500 元`、`100 點`，留白可省略
- 統一錢幣符號圖示（見下方「圖示規範」）

規範：

- 獎品文字保持可讀，不做整段倒置。
- 內容需往輪盤內側收，避免被外框吃掉。
- 中文文字以 2 至 4 字短詞最佳，過長文字需在後台限制或前端截斷。
- **頭獎格**的金額為固定值，與其他獎項一樣由 Admin 在後台設定 `cashAmount`。
  - 標題為 `頭獎`、副標顯示固定金額（例如「10,000 元」）
  - 金額由後端 `Prize.cashAmount` 提供，前端不可寫死
- 其餘獎項在格內副標顯示對應 `cashAmount`（例如「500 元」）。

#### 圖示規範（彩金制統一）

依 2026-06-03 業主會議結論，全系統以彩金為主，**所有輪盤獎項的圖示一律統一為錢幣符號**，不再每格用不同的品項插畫（手機、耳機、禮券、咖啡 …）。理由：

- 中獎內容實際上是現金，使用實體品項插畫會造成「中了卻不是這個東西」的視覺誤導。
- 統一的錢幣符號可加強「中現金 / 彩金」的識別。

實作規範：

- 前端預設圖示一律使用錢幣符號：`💰`（emoji，視為佔位）；若改用 bitmap，需是同一張金幣 / 錢袋 PNG 套到每一格。
- 顏色維持金色系，與輪盤外框、燈泡視覺一致。
- 圖示大小與位置（在獎品文字下方）所有格相同。
- 即使 `prizes.imageUrl` 仍允許 Admin 上傳，**第一階段預設不啟用 per-slot 圖片**：後端可保留欄位、前端統一渲染錢幣符號，等到後期改為禮品制時再開啟。
- 若後期確定要回到「實體禮品 + 圖示」型態，需先在設計規格中明確列出哪幾格屬於禮品、哪幾格屬於彩金，並重新評估是否要在同一個輪盤內混用兩種圖示。

### 7. 抽獎按鈕（左寬 + 右小符號）

依後續業主反饋再次調整，**底部主 CTA 改為「左寬抽獎鈕 + 右小切換鈕」一寬一窄並排**：

```text
[ ===== 🎁 抽獎 ===== ] [ ✨ ]
```

位置：包進一個 `.cta-row` 容器，**緊靠在底部分頁之上**，採絕對定位於手機容器內，底部偏移約 `124px`（= 分頁高度 88 + 分頁底部留白 18 + 額外間距 18）。容器寬度 `min(88%, 360px)`，左按鈕 `flex: 1`、右按鈕 `flex: 0 0 56px`、`gap: 14px`。

#### 7.1 左按鈕（抽獎觸發）

- **唯一的抽獎入口**。點擊時依當下選定的 tier 扣積分並轉動輪盤。
- 文字隨選定 tier 動態變化：
  - tier 為 1 次（預設 / 集點 6 點）→ 顯示「抽獎」
  - tier 為 N 次（3 / 5 / 7 / 10）→ 顯示「`N` 連抽」
  - 抽獎進行中 → 顯示「抽獎中」
- 金色膠囊造型；採 `inline-flex` + `align-items: center` + `justify-content: center`，icon 與文字同列、垂直置中。
- disabled 條件：`spinning || points < selectedTier.points`。

#### 7.2 右按鈕（連抽次數切換器）

- **不是抽獎按鈕**，只負責調整「下一次抽幾連」。
- 寬度固定 `56px`，僅顯示 `Sparkles` 符號（不放文字），保留桃紅色膠囊作為視覺差異。
- 點擊行為：在「目前可選的 tiers」中循環跳到下一個：
  1. 取 `cyclable = POINT_THRESHOLDS.filter(t => t.draws <= availableDraws)`，即所有「draws 不超過會員當前可抽次數」的 tiers。
  2. 從目前 `effectiveTierIndex` 走到 `cyclable` 中的下一個；走到尾端時 wrap 回開頭。
- **連抽次數上限與可抽次數連動**：可抽次數=5 時只能在 1/3/5 之間循環；=10 時可在 1/3/5/7/10 之間循環。
- disabled 條件：`spinning || availableDraws <= 1`（沒有可切換的 tier 時就不該點）。
- 抽獎中時與左按鈕同步 disabled，但不改變顯示符號。

#### 7.3 共用規範

- 容器以 `transform: translateX(-50%)` 水平置中；hover / active 在按鈕本身用 `translateY(…)` 即可（不需要再扣 50%）。
- 文字必須清楚，不被高光壓住。
- 當會員積分扣到目前選定的 tier 不再夠用時（例如選了 5 連抽、抽完只剩 3 點），前端以 `effectiveTierIndex = min(selectedTierIndex, maxAffordableIndex)` 自動回退到 user 還能負擔的最高 tier；只是顯示層的回退，state 仍保留使用者選擇，下次積分補回後可繼續使用。
- **連抽展開的 N 次抽獎在 prototype 階段僅播放一次輪盤動畫**，由中獎彈窗以 `N 連抽結果` 徽章標示；正式版若需個別呈現多個結果再另設計 modal。

### 7.1 排行榜頁

```text

幸運排行榜    依會員累計中獎金額
```

規範：

- 預設停留在「幸運排行榜」。
- 每列顯示：名次徽章、顯示名稱、金額（消耗點數 或 中獎彩金）、相對狀態（例如「領先」、「追趕中」）。

- 名單來源是後端合併的結果（自動計算 + `leaderboard_overrides`），前端不需區分。
- 金額需有千分位格式化。

## 動畫規範

抽獎動畫：

- 只有內盤旋轉。
- 外框燈泡、指針、背景、會員面板不旋轉。
- 旋轉時間由 Admin 設定，展示版目前約 `4.3s`。
- Admin 可設定旋轉秒數，例如 `3s`、`4.3s`、`6s`。
- 前端需依後端回傳或設定 API 套用旋轉時間，不可只寫死在 CSS。
- 使用 ease-out 類型減速。

Admin 可調整的輪盤視覺/行為設定：

```text
spinDurationMs       旋轉時間，單位毫秒
spinExtraTurns       額外旋轉圈數
spinEasing           旋轉 easing 名稱
wheelPrizeOrder      輪盤獎品位置排序
```

可點擊狀態：

- 中央旋鈕可觸發抽獎。
- 下方 CTA 可觸發抽獎。
- 抽獎中避免重複點擊。

無障礙：

- 支援 `prefers-reduced-motion`。
- 互動元素保留 focus-visible。

### 獎品文字方向固定

依 2026-06-03 業主反饋，原本實作中獎品標籤會跟著輪盤旋轉而傾斜，停盤後落在隨機角度，視覺上像是「每次旋轉中文字都不一樣」。新規範如下：

- 每個獎品標籤的世界座標旋轉角度永遠維持 0°（文字始終正立）。
- 標籤的「位置」仍跟著輪盤旋轉而沿圓周移動（與所屬色段同步），不脫離。
- 實作上每個 label 的內層 transform 需扣掉當下的 wheel rotation，例如：

  ```css
  /* label */
  transform: rotate(angle) translateY(label-radius) rotate(-(angle + rotation));
  /* 同時為 label 套用與 .wheel 相同的 transition，使 label 反向旋轉與盤面同步 */
  transition: transform 4.3s cubic-bezier(0.08, 0.86, 0.12, 1);
  ```

- 旋轉時間參數需與 `spinDurationMs` 對齊，避免 label 與盤面在動畫中錯開。

### 中獎彈窗

依 2026-06-03 業主反饋，原本底部的中獎文字 toast 改為中央彈窗，並為中獎品項加入小動畫，提升「中獎當下」的儀式感。

組成：

- 半透明深紫色 backdrop（`rgba(15, 0, 30, 0.72)`），點擊 backdrop 可關閉。
- 中央卡片：
  - 標題「恭喜中獎」（金色）；若本次為連抽，標題下方加一顆桃紅色 `N 連抽結果` 徽章
  - 採 `.result-modal__multi-tag` 樣式：膠囊、桃紅色漸層、字距 2px
  - `lastDrawCount > 1` 時顯示，否則隱藏
  - 中獎品項圖示：圓形容器，底色與文字顏色採用該獎品的 `segmentColor` / `textColor`，內顯示 emoji 或 Admin 上傳的圖片
  - 獎項等級（例如「頭獎」）+ 名稱與金額描述（例如「彩金・5,000 元」）
  - 金色「知道了」按鈕
- 卡片左右角各一顆閃爍 sparkles icon。

動畫：

- backdrop 0.18s 淡入。
- 卡片進場：`modalIn` 0.4s（縮放 0.94 → 1 + 上移 12px）。
- 中獎品項圖示：
  - 進場 `prizePop` 0.6s（scale 0.4 → 1.16 → 1，輕微擺動 -18° → +8° → 0°）。
  - 進場結束後接 `prizePulse` 1.8s 無限循環，做柔和金色光暈呼吸。
- 兩顆 sparkles 以 `sparkleSpin` 2.4s 循環擺動 + 透明度變化。
- 需支援 `prefers-reduced-motion`：所有動畫降為近似瞬時。

## Admin 後台介面設計規範

依 2026-06-03 業主會議結論：**Admin 後台不沿用前台的紫金色高級抽獎主題**，改以一般資料管理介面（dashboard / table / form）的風格設計，以提升日常調整的便利性。

### 視覺基準

- 中性灰白底色（例如 `#f7f7f9` 容器、`#ffffff` 卡片），不再使用紫色舞台、金幣、紙花。
- 文字以黑色 / 深灰為主，操作按鈕用品牌色點綴即可，不需要金屬感、發光、3D 質感。
- 不放動畫、紙花、bitmap 元素。
- 不需要手機框架；直接以一般 desktop dashboard 寬度佈局即可。

### 元件與排版

- 採用標準 UI library（Material UI、Ant Design、shadcn/ui 等擇一），不自製樣式。
- 表格 / 表單 / 篩選器以資訊密度與快速操作為主，避免裝飾性留白。
- 重要欄位（如積分、抽獎次數、彩金金額）以高對比數字呈現，但仍維持 dashboard 字級，不需「招牌字」。
- 設定型表單需提供「儲存」「重置」「最近變更稽核」三個基本動作。

### Demo 範圍

- 目前前端展示版內嵌的 `AdminConsole` 為快速 demo 用途，與此規範**無關**。
- 正式 Admin 後台應重新設計，不繼承這個外觀，也不需要與前台共用樣式檔。

### Admin 模組架構（2026-06-03 業主規範補充）

正式版 Admin 後台至少包含下列五個頂層模組，左側為導覽列、右側為主內容區。

#### A. 會員列表

兩個 tab：

```text
正式會員    accountType = verified
測試會員    accountType = test
```

- 使用 LINE 註冊者**預設**進入「正式會員」分頁。
- Admin 可在會員詳情頁將 `accountType` 切換為 `test`，該會員自動移到「測試會員」分頁。
- **黑名單會員** (`accountType = blacklisted`) 仍顯示在原本所屬分頁中，並以紅色徽章 / 灰階列底標示；不另開分頁，避免 Admin 找不到。
- 列表必備欄位：頭像、LINE 顯示名稱、`accountType`、**積分**、累計抽獎次數、最後抽獎時間、操作按鈕。
- 列上操作按鈕至少：
  - 編輯（切換 `accountType`、設定測試會員的 `testSkipCost` / `testForcePrizeId`）
  - **派發 / 扣除積分**（單一輸入框 + 備註，正數派發、負數扣除）
  - 加入 / 解除黑名單
- **測試會員的抽獎機率**：在會員詳情頁可指定「強制中此獎品」或「自訂機率」，**不依循系統預設機率**。
- 所有寫入操作（編輯、彩金 +/-、黑名單）皆透過後端 API，並寫入 `admin_action_logs`。

#### B. 遊戲規則

對應後端的下列設定，**Admin 可依既定設計規範一次調整**：

- 獎品 CRUD（含 `cashAmount`、`weight`、`segmentColor` / `textColor`、`wheelPosition`、`isConsolation`）
- 抽獎旋轉相關（`spinDurationMs` / `spinExtraTurns` / `spinEasing`）
- **抽獎門檻**（`pointThresholds` 陣列：每筆 `{ points, draws }`，預設 5 階；單抽 tier 為 `thresholds[0]`、連抽 tier 為 `thresholds[last]`）
- 成本控管閘門（`minDrawsBeforeWin` / `cooldownDrawsAfterWin` / `payoutCapEnabled` / `payoutCapRatio`）

頁面以多區塊表單呈現，每一區獨立「儲存」按鈕；表單下方顯示「最近一次由誰、何時修改」摘要，可深連到歷史紀錄。

#### C. 頁面設置

- 對應 `bottom_tabs_config`。
- 列表呈現四個（或多/少）下方導航項目，每列可編輯：
  - `label`（顯示文字）
  - `iconName`（lucide icon 名稱，附下拉預覽）
  - `sortOrder`（拖拉重排）
  - `visible`（toggle）
- `key` 為唯讀，由前端路由綁定。
- 儲存後即時反映到所有正式會員的前端，且寫入 `admin_action_logs.event = 'bottom_tabs.updated'`。

#### D. 自定模板

- 對應 `template_assets`。
- Slot 至少三個：`background`、`logo`、`wheel_frame`。
- 每個 slot 列出當前生效版本與歷史版本（縮圖、上傳者、時間），可：
  - 上傳新版本（上傳前 UI **必須顯示「目前測試開發圖片的尺寸 / 檔案規格 / 注意事項」**，避免版面跑位或圖片變形）
  - 切換生效版本（回滾）
- 建議規格區塊內容固定顯示：
  - `background`：1080 × 1920、PNG、≤ 2 MB
  - `logo`：720 × 480、去背 PNG、≤ 800 KB
  - `wheel_frame`：1254 × 1254、PNG、≤ 2 MB
- 上傳超出建議規格 ±20% 時，後端回 422 並提示，前端需 inline 顯示原因。

#### E. 系統設置

兩個分頁：

- **個人設定**
  - 變更密碼（驗舊密碼 + 設新密碼 + 確認）
  - 顯示「密碼上次更新時間」（來自 `admin_users.passwordChangedAt`）
- **歷史紀錄**
  - 列出 `admin_action_logs`，支援以下篩選：
    - 操作者（adminUserId）
    - 事件類型（event）
    - 目標資源類型（targetType）/ id
    - 日期區間
  - 列上點擊「展開」可看到 `payloadBefore` / `payloadAfter` 的差異。
  - **同分頁加入「會員抽獎歷史」搜尋框**，輸入會員 id 或 LINE 顯示名稱可導到 `GET /api/admin/users/:id/draw-history` 的列表，與 admin 操作紀錄並列瀏覽。
  - **所有管理員的操作行為皆會出現在此頁**，包括測試會員設定、彩金加減、黑名單上下線、模板更新、頁面設置更新、密碼變更等。

### Admin 介面共通規範

- 每一個寫入動作完成後需顯示成功 toast / banner，並附「於歷史紀錄查看」連結。
- 危險動作（黑名單、模板回滾、會員彩金 -X）需二次確認 modal。
- 列表頁支援關鍵字搜尋與分頁，預設每頁 25 列。
- 不沿用前台紫金色主題；採用標準 dashboard 元件（中性灰、品牌色按鈕點綴）。
