Lucky Wheels

LINE 會員幸運輪盤抽獎系統

業主版遊戲規格

遊戲規格

版本：2026-06-03

適用對象：業主、營運、客服

一、系統定位

本系統是一套 LINE 會員彩金抽獎活動。會員從 LINE 登入後，使用點數兌換出「剩餘彩金」，每抽一次扣固定金額，由系統依機率抽出該次中獎金額。所有中獎結果一律由伺服器決定，前端只負責播放動畫與顯示金額。
  • 獎項本身就是現金（彩金），第一階段不發放實體禮品。
  • 頭獎採「最高彩金累積」機制，沒人中獎時持續疊高。
  • 提供測試帳號與正式會員兩種帳號類型，正式會員不可被人工干預中獎結果。
  • 提供消耗、幸運兩種排行榜，名單可由後台微調。
  • 提供成本控管機制，後台可即時調整中獎難度與派彩上限。

二、會員與帳號類型

類型 取得方式 差異
正式會員 LINE 登入後系統自動建立，預設即為此狀態 中獎結果完全由系統決定；所有抽獎、消耗、中獎金額計入排行榜與最高彩金累積。
測試會員 由 Admin 在會員列表手動編輯切換 可設定是否扣彩金、是否強制中指定獎項，抽獎機率不依循系統預設機率。紀錄不進入排行榜、不影響最高彩金累積。僅供 Demo、驗收、客服測試使用。
黑名單 由 Admin 從正式會員或測試會員手動標記 所有抽獎與寫入請求一律被後端攔下，前端僅顯示「此帳號已被停用」等中性訊息，不揭露原因。仍可登入查看會員資料。

三、抽獎流程

  1. 會員從 LINE 進入活動頁，系統自動完成 LINE 登入。
  2. 會員以點數兌換抽獎資格，每次抽獎固定消耗 $100 彩金。
  3. 會員面板即時顯示「剩餘彩金」「可用抽獎次數」「累計抽獎次數」。可用次數為 剩餘彩金 ÷ 單次消耗彩金，由系統計算，無法手動填寫。
  4. 會員按「點擊抽獎」，前端鎖按鈕、播放輪盤動畫。
  5. 後端在伺服器端完成中獎判定後，回傳中獎獎項與金額。
  6. 動畫停止後跳出「恭喜中獎」彈窗，顯示中獎獎項與金額，並有金光動畫。
  7. 中獎金額與抽獎紀錄寫入會員資料，更新「我的獎品」與排行榜。

四、輪盤獎項與彩金規則

4.1 輪盤格數

輪盤固定為 6 格。每一格擁有獨立顏色與彩金金額，由後台維護。

4.2 預設獎項配置

等級 名稱 金額 權重 視覺色
頭獎最高彩金動態（累積值）2朱紅
二獎彩金5,000 元6琥珀
三獎彩金1,000 元14金黃
四獎彩金500 元22翡翠
五獎彩金100 元26寶藍
六獎謝謝參加0 元30紫晶

權重控制中獎機率，與輪盤上的視覺位置分開設定；後台修改視覺順序不會影響機率。

4.3 最高彩金累積機制

  • 後台可設定「基底金額」「每次未中時的累加金額」「當前累積金額」三個數值。
  • 每次有人抽獎但沒中頭獎，「當前累積金額」自動加上「累加金額」。
  • 有人中頭獎時，會員獲得「當前累積金額」當作中獎彩金，系統把累積金額重置為「基底金額」。
  • 測試帳號的抽獎不影響累積，也不會觸發重置。
顯示位置：輪盤頂端設「最高彩金」顯示區，動態金額由系統自動同步，後台改動會即時反映。

五、排行榜

榜單 計算方式 是否可後台調整
消耗排行榜 會員累計消耗的點數金額 可新增 / 修改 / 隱藏條目，可手動指定排名與顯示名稱
幸運排行榜 會員累計中獎彩金金額 同上
  • 排行榜不顯示真實 LINE 名稱與 ID，會員顯示名稱以暱稱遮罩呈現（例：陳**、王**）。
  • 測試帳號紀錄不進入任一榜單。
  • 後台手動條目與系統自動條目會合併輸出，前端不會標示哪個是手動加入的。

六、成本控管機制

為了精確控制派彩成本，系統在抽獎當下，依序通過下列三道「閘門」。任一道未通過就強制中安慰獎（消耗一次抽獎，但實際中獎金額為 0）。

閘門 規則 後台可調整
最低抽獎次數 會員需累計達到設定的抽獎次數，才有機會中獎 每次抽獎次數門檻
中獎冷卻 會員中獎後，需經過設定的次數才有機會再次中獎 冷卻次數
派彩比例上限 全系統「累計派彩 ÷ 累計消耗點數」超過設定比例時，所有抽獎一律安慰獎 是否啟用、比例上限
  • 三道閘門只對正式會員生效，測試帳號完全不受影響。
  • 被閘門攔下的抽獎仍會扣彩金、仍會寫紀錄，前端動畫表現與一般抽獎完全相同，會員不會察覺。
  • 後台 Dashboard 即時顯示累計抽獎次數、累計派彩、累計消耗、當前派彩比例，以及各閘門近期觸發次數。

七、Admin 後台模組

Admin 後台採一般 dashboard 風格設計，與前台紫金色抽獎主題分離。以下五個模組為正式版至少需具備的範圍。

7.1 會員列表

  • 分為「正式會員」與「測試會員」兩個 Tab。
  • 使用 LINE 註冊者預設進入「正式會員」分頁。
  • 管理員可在會員詳情頁將其編輯為「測試會員」，該會員會自動移動到測試會員分頁。
  • 測試會員的抽獎機率不依循系統預設機率，可由管理員指定強制中某一獎項或自訂機率。
  • 列表必備欄位：頭像、LINE 顯示名稱、帳號類型、剩餘彩金、累計抽獎次數、最後抽獎時間、操作。
  • 列上可直接執行「新增彩金」與「扣除彩金」操作，並附操作備註。
  • 可將會員標記為「黑名單」，該會員後續所有抽獎請求一律被後端攔下，前端顯示中性訊息，不揭露具體原因。
  • 黑名單會員仍顯示在原本所屬分頁中，以紅色徽章標示，便於管理員找回與解除。

7.2 遊戲規則

管理員可依照本規格的設定範圍，調整整體遊戲規則，包括：

  • 獎品 CRUD（名稱、金額、權重、視覺顏色、輪盤位置、是否為最高彩金、是否為安慰獎）
  • 輪盤旋轉時間、額外圈數、easing
  • 單次抽獎消耗彩金
  • 最高彩金累積機制的基底金額、累加金額、當前金額
  • 成本控管的最低抽獎次數、中獎冷卻、派彩比例上限

7.3 頁面設置

  • 管理員可編輯前台「下方導航列」的設定。
  • 每一格可調整顯示文字、icon、排序、是否顯示。
  • 項目本身的「key」與前端路由綁定，不可變更（避免連結失效）。

7.4 自定模板

  • 管理員可變更前端「背景圖片」與「Logo 圖片」（以及進階的輪盤外框圖）。
  • 每次上傳前，系統會在介面中明確顯示「目前測試開發圖片的尺寸與檔案規格」，提示管理員依照規格準備檔案，避免版面跑位或圖片變形。
  • 建議規格參考：背景 1080 × 1920、Logo 720 × 480 去背 PNG、輪盤外框 1254 × 1254。
  • 每個位置保留歷史版本，可隨時切換回舊版作為回滾。

7.5 系統設置

  • 個人設定：管理員可變更個人密碼（需驗證舊密碼），並顯示「密碼上次更新時間」。
  • 歷史紀錄：
    • 記錄每位會員的抽獎歷史，可依會員搜尋。
    • 所有管理員的操作行為皆完整記錄於此處，包括測試會員設定、彩金加減、黑名單上下線、頁面設置調整、模板更新、密碼變更等。
    • 每筆紀錄保留操作者、時間、變更前後值、IP 與備註。
    • 歷史紀錄無法由後台刪除或編輯。
共通規範：所有寫入型操作完成後皆顯示成功提示並連結到歷史紀錄；危險動作（黑名單、模板回滾、彩金扣除）需二次確認。

八、視覺與互動規範重點

  • 前台主要服務手機使用者，採紫金色高級抽獎活動風格。
  • 輪盤外框、燈泡、上方指針固定不動，只有內盤旋轉。
  • 中央旋鈕為 50×50 純裝飾元件，不可點擊，抽獎一律走下方主按鈕。
  • 主按鈕「點擊抽獎」固定吸附在底部分頁正上方。
  • 會員面板顯示「剩餘彩金 / 可用抽獎次數 / 累計抽獎次數」三項。
  • 中獎時以中央彈窗呈現，搭配中獎品項的金色光暈動畫。
  • 支援 prefers-reduced-motion，動畫降為近似瞬時。

九、安全規範

  • 中獎結果完全在後端產生，前端不得參與機率運算。
  • 點數、彩金、抽獎次數的所有異動皆寫入流水紀錄與稽核欄位。
  • 測試會員的覆寫設定僅在「帳號類型 = 測試會員」時生效，後端強制忽略其他類型的覆寫欄位。
  • 黑名單檢查在所有寫入型 API 入口完成，前端隱藏按鈕僅為輔助，不可被視為唯一防線。
  • 成本控管的判斷一律在伺服器完成，且不透過任何欄位讓會員察覺自己被閘門攔下。
  • 後台所有操作（儲值、帳號類型切換、黑名單、jackpot 調整、排行榜編輯、成本控管、頁面設置、模板上傳、密碼變更）皆寫稽核紀錄，且無法由後台介面刪除或編輯。
  • 抽獎 API 需防重送，同一會員短時間連點不會重複扣彩金。
  • 自定模板的圖片上傳需驗證副檔名、MIME、大小、寬高，並掃描惡意檔頭（例如 SVG 內嵌 script）。
  • Admin 密碼以單向雜湊（bcrypt / argon2）存放，變更密碼需驗證舊密碼，且歷史紀錄中不出現密碼明碼或雜湊。
